# PYM (Plan Your Money) — Системная Архитектура и Документация для Защиты ВКР

## 1. Паспорт проекта
* **Название проекта**: PYM (Plan Your Money)
* **Тип продукта**: SaaS / B2C веб-приложение (SPA) для краткосрочного оперативного прогнозирования ликвидности и контроля Cash Flow на горизонте 30–180 дней.
* **Главная задача**: Предотвращение кассовых разрывов за счет динамического математического моделирования входящих и исходящих денежных потоков взамен ручных таблиц Excel.

## 3. Модель информационной безопасности (Zero-XSS)

1. **HttpOnly, Secure, SameSite=Lax Cookie**:
   * Токен доступа JWT формируется в `AuthController.java` и передается клиенту исключительно в заголовке `Set-Cookie` с флагом `HttpOnly`.
   * JavaScript в браузере не имеет физического доступа к токену через `document.cookie`. Это исключает компрометацию пользовательской сессии при атаках типа Cross-Site Scripting (XSS).
2. **Аутентифицированный внутренний контур**:
   * Шлюзовой фильтр `JwtAuthenticationFilterFactory` валидирует подпись HMAC-SHA256, извлекает `userId` из payload и пробрасывает доверенный заголовок `X-User-Id: {userId}` внутреннему Go-сервису.
   * Прямой доступ к сервисам Go, Python и PostgreSQL из внешней сети заблокирован в Docker Compose.
3. **Безопасность внешних интеграций**:
   * **Google Calendar**: верификация заголовка `X-Goog-Channel-Token` с криптографическим `webhook_secret` пользователя.
   * **Telegram Bot**: криптографическая проверка подписи HMAC-SHA256 тела входящего запроса на основе `TELEGRAM_BOT_TOKEN` и проверка заголовка `X-Telegram-Bot-Api-Secret-Token`.

## 4. База данных: Архитектурный паттерн Schema-per-Service

* **Схема `auth_schema`**:
  * Таблица `auth_schema.users`: `id`, `email`, `password_hash`, `webhook_secret`, `created_at`.
* **Схема `finance_schema`**:
  * Таблица `finance_schema.finance_rules`: `id`, `user_id`, `title`, `amount`, `rule_type`, `category_type`, `start_date`, `end_date`, `day_of_month`, `external_id`.
  * Таблица `finance_schema.user_profiles`: `user_id` (PK), `initial_balance` (фактический баланс на счетах), `forecast_start_date` (дата отсчета "Старт"), `default_horizon_days` (глубина 30/60/90/180 дней), `safety_buffer` (неснижаемый остаток), `auto_today_start`, `currency`, `updated_at`.
  * Индекс: `CREATE INDEX idx_finance_rules_user ON finance_schema.finance_rules(user_id);`
* **Аргументация для диплома**: Отсутствие физического `FOREIGN KEY` между `auth_schema.users` и финансовыми таблицами обусловлено требованием слабой связанности (Loose Coupling). Логическая целостность обеспечивается кодом шлюза через проверенный `X-User-Id`. В браузере настройки профиля кешируются в локальном профиле (`localStorage`), обеспечивая мгновенный запуск без лишних блокирующих запросов.

## 5. Алгоритм прогнозирования ликвидности (Predictor Engine)

1. Принимает параметры: `current_balance`, `start_date`, `period_days` (30–180), `rules` (список правил).
2. Выполняет суточный цикл $d \in [0, \text{period\_days}]$:
   * Накапливает дельту дня `day_delta`:
     - Разовые события (`ONCE`): проверка `rule.start_date == current_day`.
     - Циклические события (`RECURRING`): проверка периода активности `start_date <= current_day <= end_date` и дня месяца `rule.day_of_month == current_day.day` (с учетом дней в месяце).
   * Рассчитывает остаток: $B(t) = B(t-1) + \Delta(t)$.
   * Фиксирует точки кассового разрыва: $B(t) < 0$.

## 6. Пользовательский интерфейс и Context-Driven Manipulation

* **Кастомный SVG-график**:
  * Ступенчатая линия тренда (`stepAfter`) отражает дискретную природу финансовых транзакций.
  * Зеленые импульсные спайки вверх — поступления (доход).
  * Красные импульсные спайки вниз — списания (расход).
  * Красная пунктирная линия `0 ₽ Limit` и градиентная зона дефицита под ней.
* **Кастомное контекстное меню по ПКМ (Правый клик мыши)**:
  * Активация на графике с математической привязкой к дате точки под курсором.
  * Пункты:
    - ➕ «Добавить правило...» (автоподстановка даты)
    - 📉 «Добавить расход (-) с даты» (предустановка `EXPENSE`)
    - 📈 «Добавить доход (+) с даты» (предустановка `INCOME`)
    - 🔍 «Показать срез баланса» (модальное окно `DaySliceModal` с входящим/исходящим остатком и транзакциями)
  * Автоматический клампинг координат к границам экрана и закрытие по `Escape` или внешнему клику.

## 7. Чек-лист для доклада на защите диплома

1. **Новизна и практическая ценность**: Замена пассивного учета предиктивным анализом ликвидности.
2. **Обоснование полиглотного стека**:
   - Java — промышленный стандарт для шлюзов безопасности и реактивной фильтрации.
   - Go — низкое потребление памяти и быстрый доступ к БД для CRUD операций.
   - Python — гибкое и выразительное математическое ядро для векторных расчетов.
3. **Безопасность**: Полная изоляция токенов от клиентского JS в HttpOnly Cookie.
4. **Отказоустойчивость**: Микросервисы изолированы в Docker; сбой калькулятора или шлюза не нарушает целостности данных в БД.
